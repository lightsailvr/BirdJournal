# BirdJournal — design decisions (grill sessions, 2026-09-26)

Source of truth for choices made on top of `spec.md`. Where this file and the spec disagree, this file wins.

## Product
- Glasses-first. The lens is the primary UI; the phone gets a minimal screen in phase D and social features later (out of scope).
- Personal project, published personally. Only the latest iOS is supported: deployment target iOS 27, Swift 6 language mode, Xcode 27.
- Android: out of scope. Web-app path: dropped (Web Apps have no mic or camera).

## Toolkit facts that shape the design
- Ambient audio only arrives in-band on a camera stream (`StreamConfiguration(audioCodec: .pcm(...))`). HFP is 8 kHz and beamformed to the wearer's voice; not usable.
- Camera audio, Inputs, photo capture, motion, speech and voice invocations are experimental in SDK 1.0.0: Dev Mode and Beta channel only.
- Real glasses do not deliver the Back event to apps (DAT 1.0.0 Inputs docs, "Current limitations": the on-glasses path is not wired yet; `consumeBack` only matters on the mock). The Neural Band's middle-finger tap is the system's back gesture, and since every view an app sends is the root as far as the glasses know, it ends the display session from any card (seen on hardware, #24). The app must give its own way back: swipe right on a card returns to the list. The two-finger temple tap also ends the session.
- An app that subscribes to Inputs receives Nav and Select itself; the glasses neither moved focus between tappable rows on the species list nor scrolled a tall card (#24, on hardware; the Inputs docs: subscribing "avoids consuming interactions that the system or on-glasses display would otherwise handle"). So a list is a menu the app drives: it keeps the selection, highlights it and re-sends; and long content is paged by the app. A Display button click still arrives (the details page's "Add to my list").
- Display: one root `FlexBox` per `send`, 600×600 additive display, dims and sleeps on inactivity. Images from bundled `UIImage` work offline. The docs say a tall view scrolls vertically, but with Inputs attached the glasses hand swipe up/down to the app and do not scroll (2026-09-27, #24), and the mock preview anchors overflow at the bottom. So every send fits the canvas and the app pages: a species has a photo page and a details page.
- A bundled `UIImage` is laid out at its pixel size on the 600-pixel canvas (measured on the mock in #7, to verify on hardware): a 600 px crop fills the card and pushes the text off it. Lens crops are 552 × 368 (3:2): the card's width under 24 px of padding, short enough that the name stays on the first screenful (#24; the 260 px square of #7 sat beside the name and left half the canvas blank).
- Only one third-party app can be registered in Dev Mode at a time. Bundle IDs may not contain `-`.
- One device session per device (`DeviceSessionError.sessionAlreadyExists`). The listening run (#9) starts one session and shares it between the camera stream, Display and Inputs; the single-capability screens and mock tests still start their own.
- Display 1.0.0 has no wake call. The docs say the display dims after 20 s and sleeps at 25 s without ending the session; the app re-sends the current card (the species list or the species card with its refreshed status strip) on each new species, and whether that wakes a sleeping display is checked on hardware (#9, #24).
- MockDeviceKit cannot inject audio frames; sound-ID tests run on recorded files. With a still-image feed it delivers no video frames either (#9), so the frame path is tested with a stand-in source and the real stream's frames on hardware.

## Audio and identification
- Glasses stream: camera at `.low` resolution, lowest frame rate, audio PCM mono. Sample rate 44.1 kHz (chosen in the phase A spike), resampled to the model rate.
- Video frames are not used for identification. The most recent frame at the moment of the "Add to my list" tap (#24; it was the confirm tap in #9) is stored with the sighting as a JPEG under Application Support/Frames, referenced by a relative path; the camera-assist re-ranker is out of scope.
- Model: BirdNET+ V3.0 preview 3.1 (11,560 species, 32 kHz input, CC BY-SA 4.0 weights, "Powered by BirdNET" attribution). Pinned to the exact Zenodo file. Engine sits behind a protocol so v2.4 can be swapped in.
- Geo prior: BirdNET geomodel v3.0.4 (Apache-2.0), raw lat/lon/week input, used as a pre-filter with the reference threshold 0.03. No GBIF/H3 tables in v1.
- Runtime: ONNX Runtime via the official Swift package (`microsoft/onnxruntime-swift-package-manager`), consumed through the fork `lightsailvr/onnxruntime-swift-package-manager` so Xcode Cloud can fetch it. Core ML conversion is a later optimization, not a dependency.
- Audio source is a protocol with three implementations: glasses stream, phone mic, WAV file (tests).
- Windows: 3 s with 1.5 s overlap; a species enters the stack after two windows above threshold. Thresholds tuned in phase B.
- Ring buffer exists only for live playback. No audio is saved to the album.
- Location: "when in use" permission; Core Location live updates read for the whole run and held through the background by a `CLBackgroundActivitySession` (`UIBackgroundModes` has `location`), so every add records a fresh fix (#44, which replaced the one fix at start plus a ten-minute refresh).
- Background: the app must keep listening with the phone locked (audio + processing + Bluetooth background modes). Verified in phase A.

## Lens UI
- Gestures: swipe left/right = Nav, swipe up/down = Nav too (selection on the list, photo ⇄ details on a species; the glasses do not scroll for an app that subscribes to Inputs), tap = Select. Middle-finger tap and two-finger tap = quit (system; Back never reaches the app on real glasses).
- Page map (#24, replaces the #7 photo/description/confirm/saved pages): the root is the **species list** ("N species heard", one row per species heard, newest last: name, match rate, a photo icon when the pack has a card, a check when added), driven as a menu: swipe down/up move the highlighted row, a tap or swipe left opens it. The list is paged five rows at a time around the selection (a re-send starts at the top and the glasses do not scroll); the hint line says which page. Two pages per species: the **photo page** (the photo first and full width, the common name with the match rate beside it, the status strip "4 species · 2 of 4" with "· Added" once added, and the hint "Swipe down for more information · swipe right: all species"; a tap does nothing, so no bird is added by accident) and, on swipe down, the **details page** (name and match rate, field marks, size · habitat, the photo credit and the **"Add to my list"** primary button, or "Added to my list ✓"). Swipe up returns to the photo. On either page swipe left is the next species' photo and **swipe right is back to the list** (the only way back, since Back never reaches the app), with that species selected. Every page is one screenful inside the word budget.
- "Add to my list" saves in one action: the sighting is written with the camera frame from the moment of the tap. Both a Display button click and an Inputs Select on the details page save. A press delivered both ways (the open question from #7/#9) is two saves of one species within a second, which the adapter drops as an echo; a later tap on an added species' details page saves again and updates the sighting (spec user story 33). There is no confirm page. On the list, an Inputs Select opens the highlighted row.
- Stack never reorders; new species append at the end. A new species changes the status strip and the list but never moves the wearer off their card and never sends them to the root. Back from the list ends the session; Back from a card returns to the list.
- Photo-first cards: close-up crops with dark backgrounds preferred. Text ≤ ~40 words per **screenful** (the card's first screenful is strip, photo, name and match rate; the second is the text, credit and button); the list splits its rows into screenfuls the same way.
- Settled on hardware (#24): the glasses neither scroll a tall view nor move focus between tappable rows while the app subscribes to Inputs (swipes reach the app instead); the middle-finger tap ends the session (Back never reaches the app). Still to verify (DAT-SETUP-CHECKLIST.md): whether Select on the details page's button arrives as a click, an Inputs select or both (both add, deduplicated).
- Audio chirp on new candidate: off by default.
- Session start: phone button in v1; "Hey Meta, start BirdJournal" once the Developer Center approves Voice Invocation.

## Species pack
- Region v1: Los Angeles area, ~150 species with photos and descriptions. All BirdNET species remain identifiable by name.
- LA pack bundled in the app binary (offline on first launch). Other packs downloaded from GitHub Releases via a JSON index into app storage.
- Pack = zip of SQLite + pre-sized JPEGs (lens 552 × 368, see the Display image-size fact above; phone ~1200 px). A bird too tall for the card-shaped crop keeps its head and loses its tail.
- Pack builder (Python) adds a detector step (COCO "bird") to crop close-ups, scores crops on bird area, background luminance and sharpness, keeps top 3–5 per species, with a manual override list.
- Photo licenses: CC0, CC BY and CC BY-NC. Every photo carries observer, license and source URL. Credit shown on the species card and in a full credits screen on the phone.
- Pack builder facts (#8): the iNaturalist API is the default metadata source (the Open Data dump is tens of GB; the DuckDB path over it exists for full rebuilds), ordered newest first because the most-faved observations are the oddities (every top-voted California Towhee was leucistic). Detector: COCO SSD MobileNet v1 (ONNX zoo, Apache-2.0); it misses birds under about 5 % of the frame, which are poor cards anyway. Crops below 0.4 sharpness are dropped before ranking; hand-held and dead birds still need the override file. Built packs are not committed: `packs/manifest.json` pins each to a zip on this repo's GitHub Releases and `scripts/download-pack.sh` fetches it (since #12; the ten-species pack was committed while it was 9 MB).
- Descriptions (#12) are cut from Wikipedia by rule, not written by hand: about 150 species is too many to author and keep reproducible, and the issue asked for Wikipedia-derived text. `overrides.json` replaces any field for a species the rules serve badly. Lookalikes stay empty in v1: no lens page shows them.

## Phase A go/no-go (issue #3) — GO, 2026-09-26
Run: glasses source, 44.1 kHz mono, `.low` at 2 fps, iPhone 17 Pro locked in a pocket, 19 min 45 s (`spike-20260926-193507.log`).
- Sample rate: **44.1 kHz**. 48 kHz is untested: the first attempt stalled on the Meta AI microphone grant, not on the rate.
- Coverage: 1,182.0 s of audio in 1,185.2 s of wall time (99.7 %; the shortfall is stream startup). Zero gaps over 2 s. Chunks every 23.2 ms on average (1,024 samples); the longest interval between chunks was 671 ms.
- Latency above best: 39–89 ms mean per 30 s interval, 689 ms worst. No upward drift over the run, so the link does not back up. Absolute glasses latency is unknown: presentation times are not on the phone's host clock (first offset 882,188 s).
- Glasses battery 100 → 88 % (about 0.6 %/min, so roughly 2.5–3 h of listening from full). Glasses thermal `none` throughout. Phone battery 65 → 65 %, thermal `nominal`.
- Background: status lines kept arriving every 30 s while locked (`background_locked` for 37 of 40 intervals). The Bluetooth and external-accessory modes are enough; no `AVAudioSession` is needed on the glasses path.
- One `stream_error "Critical error, the stream should end"` arrived 2 s after the app went to the background, but the stream kept `streaming` and audio never stopped. Watch for it; do not stop the source on stream errors alone.
- The first audio chunk after `streaming` was empty (0 samples); consumers must tolerate empty chunks.
- Doff does **not** pause (`spike-20260926-195716.log`): 12 s after taking the glasses off, the device ended the session (`session_error "Session ended by device"`, session and stream `stopped`) and the link dropped. After putting them back on, the glasses were `donned` and `connected` within about 35 s, but the session stayed stopped and no audio returned. The app must start a new session itself once the glasses are worn and connected again; waiting for `.paused` → `.started` never happens. Touchpad-tap pause is still untested.
- Verdict: **GO** for the audio path: continuous, survives a locked phone, and costs about 12 % glasses battery per 20 minutes. Follow-up needed: automatic session restart after doff/don (the listening session must survive taking the glasses off). Built in #10, see "Pause, disconnect and error handling".

## Los Angeles pack at 160 species (issue #12) — built 2026-09-27
- **The list**: the 150 bird species with the most research-grade iNaturalist observations in Los Angeles County (place 962, queried 2026-09-27), minus hybrids, the domestic Swan and Greylag Geese and the California Condor (no BirdNET class), plus ten species heard more than seen (Mountain Chickadee, Hutton's and Bell's Vireos, Cactus and Canyon Wrens, Common Poorwill, California Gnatcatcher, Greater Roadrunner, Western Screech Owl, Swainson's Thrush): 160 species, in observation order, in `packbuilder/packs/us-ca-la/pack.json`. Established exotics stay in (parrots, Red-whiskered Bulbul, Scaly-breasted Munia, Pin-tailed Whydah, Indian Peafowl, Egyptian Goose): they are what one hears in LA. Names are the BirdNET+ label file's (iNaturalist's Vireo swainsoni is BirdNET's Vireo gilvus; "Myrtle Warbler", "Rock Dove", "Scarlet Flycatcher" are the label file's spellings), so the engine, the lens and the album agree; `tests/test_definition.py` checks every entry against the label file.
- **Descriptions** come from each species' English Wikipedia article (the plain-text extract, cached by title): the summary is the lead's first sentences (60 words), the field marks are the Description section's plumage sentences with measurement sentences skipped (20 words, the details page's budget after name, size and habitat, credit and button), the size is the body length (a figure in a sentence that names the wing, tail, bill or egg counts only when its own clause says "long" or "length"; millimetres, metres and inches converted; 147 of 160 articles give one, the rest none rather than a wrong one), the habitat is the three habitat terms the article uses most from a fixed vocabulary. An article whose lead does not name the binomial (iNaturalist's "Bushtit" link lands on the family page) is refused and logged so the override file can fill it. The text is CC BY-SA 4.0: every species row records the article revision (`description_source`), the LICENSE lists them under "Text credits", the phone's species page and the credits screen link them. Pack schema 2.
- **Builder**: `large` renditions are downloaded eight at a time (the bucket was the slow step at 160 × 60 candidates); the rest of the pipeline is unchanged. The full build is reproducible from the committed `pack.json`, `overrides.json` and `wikipedia.lock.json` plus the builder's cache (API pages pinned to `inat_created_before`, Wikipedia pages by title); from a clean cache the iNaturalist side drifts only by deletions, and Wikipedia's plain-text extract API serves only the current revision, so the lock file cannot fetch an old one: the build warns for every article whose revision moved since the lock and re-pins it, which makes text drift a visible diff rather than a silent change.
- **Distribution**: the built pack is a GitHub Release asset (`pack-us-ca-la-v1`, `us-ca-la.zip`) pinned by SHA-256 in `packs/manifest.json`; `scripts/download-pack.sh` fetches and unpacks it and the Xcode Cloud post-clone hook runs it after the models. The repository was private then, so Xcode Cloud needed a `GITHUB_TOKEN` environment variable with contents read access on the workflow; it has been public since #13 and the download needs no credentials.
- **Result**: 160 species, 793 photos (five each but for White-throated Swift, Great Horned Owl and Common Yellowthroat with four and Yellow-chevroned Parakeet and American Barn Owl with three; no photo gap after the Bald Eagle override widened its candidate list to 200 and pinned the adults over the brown juveniles the score preferred), every species described, 147 with a size and 155 with a habitat line; 161 MB on disk (32 MB lens, 128 MB phone crops), a 165 MB zip. App-size check: the pack ships as the `BirdJournalKit_Pack.bundle` resource bundle, 161 MB in the built app against 11 MB for the ten-species pack (the debug simulator build is 589 MB in all, 77 MB of it the models), so the increase is 150 MB: under the 200 MB budget with the 1200 px phone crops kept. The first build took about 75 minutes (9,600 photo downloads); a rebuild from the cache takes about six. Originals smaller than the 552 × 368 lens crop are now skipped (five 300-pixel parakeet and gull photos had been upscaled into cards), and the phone crop never cuts tighter than the lens crop.
- Not in this issue: lookalikes (the table stays empty; no lens page shows them), a hand-written pass over the 160 derived texts beyond the override file, downloadable packs on the phone (#13).

## Album and credits on the phone (issue #11) — built 2026-09-27
- The phone's root list gets an **Album** row (sighting count) and a **Settings** screen; Settings holds the species pack screen and the **Credits** screen, so the credits are reachable from settings as the spec asks.
- Album: every `Sighting` newest first (`Sighting.newestFirst()`, a `FetchDescriptor` the `@Query` uses), one row each with the **2x center crop** of the stored frame (`FrameCrop` in the `Album` module: the middle half of each side, on whole pixels; the frame stays whole on disk), the species name, the date and the place. Tapping a row shows the crop across the screen and the record (names, when, where, match, glasses or phone). Species names come from the bundled pack by scientific name (the pack's `birdnet_label` column holds the scientific name, not the full label), else from the label's own common name, so an unpacked species is still named.
- Place: a sighting stores only a coordinate, so the album reverse-geocodes it with MapKit's `MKReverseGeocodingRequest` (iOS 26+; `CLGeocoder` is deprecated) once per run and coordinate, cached in `PlaceNames`, and shows "34.14° N, 118.29° W" until a name arrives or for good when offline. No location reads "No location".
- Frames are read as data, not by path: `URL.path()` percent-encodes the space in "Application Support", so `UIImage(contentsOfFile:)` on it finds nothing. The frame store is one per app (`BirdJournalApp.makeFrameStore()`), shared by the recorder and the screens through the `frameStore` environment value.
- Credits: "Powered by BirdNET" first, then both models (`ModelCredits` in `Identification`: BirdNET+ V3.0 preview 3.1, CC BY-SA 4.0, the Zenodo DOI; geomodel v3.0.4, Apache-2.0, the GitHub release) each linking its license deed and source, with the license and terms texts read from the bundled `Models` folder (`TERMS_OF_USE.txt` is Zenodo's terms naming CC BY-SA 4.0; `LICENSE-MODELS.md` and `ACCEPTABLE_USE.md` are the geomodel's; all pinned in `models/manifest.json`), then every photo in the bundled pack grouped by species with observer, license (linked to the Creative Commons deed, `PackPhoto.licenseURL`) and the observation link, and the pack's LICENSE text verbatim.
- Debug launch flags for simulator screenshots: `-inMemoryAlbum YES` keeps the album in memory and its frames in a fresh tmp folder; `-autoAlbum seed` seeds three sightings with generated frames and opens the album (`seed-detail` opens the newest); `-autoCredits YES` opens Settings then Credits. _Replaced in #28 by `-seedJournal YES` and `-autoScreen <name>`; see "The phone as a field journal"._
- Not in this issue: deleting sightings, a session record, sharing. Verified on the simulator: order, crop (the seed frame's border is cropped away), place names online, credits with all 50 photos.

## Pause, disconnect and error handling (issue #10) — built 2026-09-27, hardware run pending
- The listening run survives the glasses. Phase A showed a doff does not pause: the glasses end the session ("Session ended by device") and drop the link, and walking out of range looks the same. So when a session stops on the device side the run reads the glasses' state to tell the cases apart: `donState == .doffed` is a doff, a link that is not `.connected` is a lost link, and glasses still worn and connected for a 2 s grace period (a link drop can be reported a beat after the session ends) is the wearer quitting (two-finger or middle-finger tap), which ends the run as before.
- A doff or a lost link **pauses** the run instead of ending it: the lens releases Display and Inputs but keeps its pages, selection and saved marks (`GlassesLensSession.Phase.suspended`); the audio source drops the camera but keeps the engine's chunk stream open (the engine sees a silence, not an end, so the stack survives); the phone shows "Paused: glasses off" or "Paused: glasses disconnected" with Stop as the way out. The run then waits, as long as it takes, for the glasses to be connected and not doffed, starts a new session itself, puts the same pages back on the lens and continues the stream on it (three tries, 5 s apart; then the run ends failed and the Start button is the restart). Nothing restarts from the phone.
- A session the toolkit pauses (`.paused`, the touchpad; the mock's `captouch.tap()` does this) is shown on the phone as "Paused by the glasses" and resumes with the session; the lens re-sends the current card in case the display dropped it. Untested on hardware.
- A session that ends with a thermal, battery, peak-power, glasses-app-update or SDK-version error ends the run failed rather than waiting: the glasses will not restart it until the wearer does something.
- Problems the wearer should know about while the lens is reachable are a **problem page** (`LensPage.problem`) over whatever page they were on: "No location" when the first fix is denied or does not arrive (identification carries on without the regional filter, as decided in #6), and "Connection lost" as the first card after a dropped link comes back. Swipe right, Back or a tap is the way back to the covered page; the other swipes stay; species heard meanwhile append behind it. A doff and don shows no page: it was the wearer's own doing. The phone mirrors the card and shows the location state.
- Glasses that leave again during a resume are waited for again. Stop from the phone in any active phase (listening, deciding, paused, reconnecting) cancels the reconnection and tears down the lens, engine, stream and session the same way; every listener token lives in a bag that is emptied on every suspension and stop, so three start-stop cycles leave nothing behind (mock test; the run deallocates after).
- Verified on the mock: doff + power off then power on + don resumes the pages and the audio without a restart; power off while worn is a lost link and the return shows "Connection lost" with swipe right back; the touchpad pause and resume; Stop while paused; no location; three cycles. To verify on the glasses (DAT-SETUP-CHECKLIST.md): the real doff/don timings, walking out of range and back, the touchpad, and that a quit still reads "Ended by the glasses" after the grace period.

## Downloadable regional packs (issue #13) — built 2026-09-27
- **The index**: `index.json` on the rolling `packs` release of this repository (`PackIndex.defaultURL`), written by `scripts/publish-pack-index.sh` from `packs/manifest.json` (id, name, version, the zip's release URL, SHA-256, byte count), which now also carries each pack's `name` and a `bundled` flag: `scripts/download-pack.sh` fetches only the bundled packs into `packs/` (everything there ships in the app), `scripts/build-pack.sh` writes a non-bundled pack to `build/packs/<id>/`, and `scripts/pin-pack.sh` keeps the flag. The index lists the bundled pack too, so one file describes every pack; the phone shows it as "Included with the app" and never offers it.
- **The repository is public** (made so on 2026-09-27 for this issue: the phone fetches the index and the zips with no credentials, and GitHub serves private release assets only with a token, which an app must not ship). The project is MIT-licensed (`LICENSE` at the root; the models and packs carry their own), the photos are CC0, CC BY and CC BY-NC with full attribution, so redistribution is lawful, and the DAT `ClientToken` and `MetaAppID` in `Info.plist` are attestation identifiers that ship inside every app's bundle, not secrets. Verified after the change: an anonymous fetch of the index and of the San Diego zip answers 200, and the app on the simulator downloads the pack from the real index with no override. `PackIndex.defaultURL` and the `repo` in `scripts/publish-pack-index.sh` and `scripts/download-pack.sh` are the three places that name the repository; the `-packIndexURL <url>` and `-autoDownloadPack <id>` debug flags point a simulator run at a local server (`python3 -m http.server` over a folder with `index.json` and the zips) when a pack is not published yet.
- **On the phone**: `PackLibrary` (in the `Pack` module, `@MainActor @Observable`) holds the bundled pack, every download under Application Support/Packs (excluded from backup: a pack is re-downloadable) and the index; the lens, the album and the credits look species and photos up across all packs, bundled first, so a species in two packs shows the bundled pack's card and a photo id resolves to whichever pack has it (two packs sharing a species share its iNaturalist photos). A download streams to tmp with progress, the SHA-256 is checked against the index, the zip is unpacked into `<id>.unpacking` by a small zip reader of our own (`ZipArchive`: stored and deflated entries as Python's `zipfile` writes them, CRC-checked, no zip64, entry names that escape the folder refused; Apple's Compression framework inflates, so no dependency), opened to prove it is a readable pack, then moved into place with `installed.json` recording the descriptor. A newer version in the index is offered as an update over an installed pack. Deleting removes the folder; the species are gone from the lens and the album at once (the album falls back to the label's common name).
- **Second pack**: `us-ca-sd`, San Diego County, the 40 most-observed species (place 829, queried 2026-09-27) as a starter: 40 species, 200 photos, 39 MB, release `pack-us-ca-sd-v1`. Widening it to the LA pack's 150-plus-heard-more-than-seen shape is content work for a later issue. The builder now retries dropped connections and 5xx answers (`http.py`); one `RemoteDisconnected` had ended a build.
- **Found on the way**: `URL.path()` percent-encodes the space in "Application Support" (the album had noted it); every path call in the pack code uses `path(percentEncoded: false)` and a test installs into a folder with a space. Verified on the simulator: the index fetched over HTTP, the San Diego pack downloaded with a progress bar, verified, unpacked and listed with its species; the install surviving a relaunch. Not verified on hardware: a species from a downloaded pack on the lens (the lookups are the same code path as the bundled pack's).

## Pack text that never ends mid-phrase, and the bundled pack's updates (issues #32 and #33) — built 2026-09-27
- **The rule** (#32): 58 of the 160 Los Angeles species had field marks cut mid-phrase with an ellipsis ("…buff or rust-colored streaks at…"), because the builder clipped the first plumage sentence at the 20-word budget. Now `take_sentences` takes whole sentences that fit, skips a sentence that does not for a later one that does, falls back to the first sentence's longest clause that fits (a comma, semicolon, colon, "and", "but", "while" or "with" boundary keeping at least half the budget, closed with a full stop), and otherwise returns nothing so the next source (the lead, then non-measurement sentences) gets its turn; a species with no fitting text has empty field marks and the lens shows its summary. Text never ends with an ellipsis; `SpeciesPackTests` checks the bundled pack for one.
- **The room**: the Display DSL has three text styles (heading, body, meta), so the details page sets the field marks in `meta` with the primary colour (`LensElement.passage`), and the field-marks budget doubles to 40 words (`FIELD_MARKS_WORDS`, `LensCardRenderer.detailsWordBudget` = 64 with the name, match rate, size and habitat, credit and button). ## Species list: calling now first, the highlight following the bird (issue #42) — built 2026-10-02, hardware check pending
- **The stack and the card pages never reorder**; "Stack never reorders" under "Lens UI" stands, since it protects the card the wearer is reading and the indices the pages, the saved marks and the selection use. The **list page gets a presentation order** (`SpeciesListOrder`, Identification) computed from the stack and a session clock on every update, with hysteresis so a chorus does not shuffle it. Raw recency re-sorted on every window is rejected: on a five-row lens page it jitters, and the glasses re-send from the top.
- **Calling now**: a species whose last window at or above the threshold (`Candidate.lastHeardAt`) is within the last **6 s** of session time (one 3 s window plus two 1.5 s hops, so one missed window does not drop the marker). Several species can be calling at once. The session clock is seconds since the run started listening (`ListeningSession.sessionTime`, the clock `CandidateRow` already read heard times against); the engine's window times run from the first chunk, a beat later, which the 6 s absorbs.
- **The order**: the calling section first (the newest caller, then the bird calling the longest, then the others newest first; "calling since" is when the species entered the section, not its last window, so two birds alternating keep their rows; with a third caller the previous newest drops to row three and row two stays put), then everything else most recently heard first, so a bird that goes quiet drops in at the top of that section and birds heard once sink on their own.
- **Marking**: a calling row on the lens has the speaker icon (`speakerWithThreeArcs`) before the name and the primary text colour; the selection keeps its caret and card background, so the two coincide. The photo page's strip gains "· calling now" for its own bird or "· Now: <name>" (the newest caller) when another is calling; the details page carries a strip with the same words only then, paid for out of the field marks' budget. On the phone a calling row reads "Calling now" in moss with a waveform glyph (static under Reduce Motion) and a moss ring on the thumbnail; the supporting text then ages "Heard just now" → "Heard N min ago" on a once-a-second tick while listening (it was computed only on render before).
- **Selection on the lens is species-keyed**: unpinned until the wearer swipes, the highlight sits on row one, so the calling bird is the highlighted row and a tap opens it. Swipe down or up pins it to a species (`LensStateMachine.pinnedSpecies`) and it stays on that bird as the list moves under it; a pinned bird pushed onto another page pages the view with it (the list pages by row position). **Swipe right on the list**, unused before, unpins and returns to the top. Opening a card leaves the pin as it was; paging to the next species on a card pins to that species, so coming back lands on it. Every other gesture is unchanged.
- **Turning the marker off**: a lapse changes nothing in the stack, so `GlassesLensSession` keeps the session clock's origin from the latest update and schedules one re-send at the lapse the order reports (one send per calling episode), and re-evaluates the order before the pages go back on the lens after a suspension. **Open risk, from the Toolkit facts**: a send may wake a dimmed display. To check on the glasses: let a bird's marker lapse with the display dimmed; if the re-send wakes it, fall back to clearing the marker on the next stack change only and record that here.
- **The phone** shows the same order with animated moves (none under Reduce Motion); the Review button can move under a thumb during a chorus, accepted for the glance use case. `ListeningCoordinator.orderedCandidates` is the order over the current stack; the remembered order is refreshed with the waveform (12 Hz, written only when it moves) and settled with nothing calling at Stop, so the review after a run is by recency.
- **Verified on the mock**: the list order, the marks and the strip, the pin surviving a card visit, and the lapse re-send (`LensMockSmokeTests`); the phone list with the example soundscape (`ListenUITests`). **Not verified on hardware**: the lapse re-send against the dimmed display (above), and the speaker icon's rendering on the real lens.

- **`ReferenceSounds`** (the app's one playback model, in the environment) plays through a `SoundPlayer` (`AVSoundPlayer` over `AVAudioPlayer`; a mock in the tests) and owns the audio-session rule: a phone-microphone run already holds the session, now `.playAndRecord` with `.measurement`, `.allowBluetoothA2DP` and `.defaultToSpeaker` (the speaker, not the earpiece; never `.allowBluetoothHFP`, which would take the glasses' 8 kHz mic as the input), so the clip plays in it and leaves it alone; otherwise (no run, or a glasses run, whose audio arrives on the camera stream with no session) the clip takes the session in `.playback` and releases it with `.notifyOthersOnDeactivation`, unless a phone run started meanwhile and made it its own. Activation and release run in order on one serial queue, off the main thread. A stop, or a second tap, while the session is still being taken cancels the clip before it starts. A phone run that stops mid-clip deactivates the session under the player, which then stops without a delegate call; `ReferenceSounds` ends any clip still marked playing 1 s past its length with the player silent, so a lost callback never leaves listening silenced.
- **Suppression, not a pause**: one `AudioSuppression` (Identification) is shared by `ReferenceSounds` and both listening sessions (the phone's and the one inside the glasses run); `ListeningSession` wraps its source in a `SuppressedAudioSource`, which passes each chunk on silenced (same length and time, so the windows and the run's clock stay put) while a clip plays and for 1.5 s after it ends, the Bluetooth speaker's output delay plus the glasses stream's (the issue said about 1 s; the tail is to be checked on hardware in phase 4). Silence, not dropped chunks: dropping would splice the audio either side into one window and pull the engine's clock behind the run's. The waveform still moves during a clip (the meter is inside the suppression).
