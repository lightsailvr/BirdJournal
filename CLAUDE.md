# BirdJournal

Bird identification on Meta Ray-Ban Display glasses. iOS 27, Swift 6, SwiftUI, Meta Wearables Device Access Toolkit 1.0.0, BirdNET+ V3.0 via ONNX Runtime.

Read before working: `DECISIONS.md` (settled design choices, wins over `spec.md`), `DAT-SETUP-CHECKLIST.md` (toolkit facts and verification steps), `docs/spec-v1-glasses-bird-id.md` (the v1 spec).

Layout: `BirdJournal/` is the Xcode project (the app target: `RootView` with the Listen / Journal / Field Guide tabs (and Circles in builds with accounts), `Listen/` with the `ListeningCoordinator` over both audio sources, `Journal/`, `Guide/`, `Packs/`, `Share/`, `Settings/` with the DEBUG-only `DeveloperView`, `Design/` with the tokens, the phone sessions under `Listening/` and `Audio/`, the reference-clip playback under `Sounds/`, the recorder and place names under `Album/`, and the glasses adapter under `Glasses/` and `Lens/`; `BirdJournalUITests/` holds the XCUITest target) and `BirdJournal/BirdJournalKit/` the local package with the `Identification`, `LensSession`, `Pack` and `Album` modules (one test target each, none depends on the toolkit; the glasses adapter and Mock Device Kit tests live in the app target); `infra/` the backend's CDK (Python) stack, one `BirdJournal` stack in us-west-2 in the shared Lightsail VR account (`lsvr-admin`): Cognito with Apple and Google, an HTTP API, FastAPI on Lambda, DynamoDB, all tagged `project=birdjournal`, plus a budget (`infra/scripts/accounts-wizard.sh` for the console-only steps, `infra/scripts/deploy.sh` to deploy; see `infra/README.md`); `backend/` the FastAPI service (uv project) with the in-process API test harness; the app's optional account is under `BirdJournal/BirdJournal/Account/` and its circles (the Circles tab, the client, the join screen) under `BirdJournal/BirdJournal/Circles/`; the invite domain's pages are in `infra/site/` and its DNS steps in `infra/scripts/circles-wizard.sh`; `packbuilder/` the Python species-pack builder (uv project; `scripts/build-pack.sh` builds a pack from `packbuilder/packs/<id>/` into `packs/<id>/`, which the `Pack` target's `Packs` resource folder symlinks so the bundled LA pack ships in the package bundle; built packs are not committed: `packs/manifest.json` pins them to GitHub Release zips, `scripts/download-pack.sh` fetches the bundled one and `scripts/publish-pack-index.sh` lists them all as `index.json` on the `packs` release for the phone to download); `docs/` specs and ADRs; `art/` the card-art prompt templates, ComfyUI workflows and comfybox setup (painted on the home GPU box over the tailnet by `packbuilder.art` and `packbuilder.comfy`; see `art/README.md`); `models/` the pinned model manifest (the `Identification` target's `Models` resource folder is a symlink to it, so the model files ship in the package bundle); `fixtures/` the labeled-clip manifest for engine tests (audio gitignored); `scripts/` build and download scripts; `BirdJournal/ci_scripts/` Xcode Cloud hooks (post-clone fetches the models and the bundled pack from this public repo's GitHub Releases).

Build and test: `scripts/build-and-test.sh` (iOS 27 simulator; `swift test` does not work because the toolkit is iOS-only). It builds once, primes a new simulator's StoreKit with one short tip jar run (#93: otherwise its first tip waits on a sandbox sign-in), then runs the app's tests without the Mock Device Kit suites, the Mock Device Kit suites on their own, and the package tests; a failure in one run does not stop the next, and the script exits non-zero if any failed. Give it xcodebuild test arguments for one app run instead (`scripts/build-and-test.sh -only-testing:BirdJournalUITests`; `--package -only-testing:LensSessionTests` for the package). Logs are in `build/test-logs/`; the terminal shows only errors and test results (`BIRDJOURNAL_VERBOSE=1` for everything). The app scheme's tests include `BirdJournalUITests` (XCUITest, real taps on the running app).
- **One simulator per agent.** Agents run tests in parallel, so set `BIRDJOURNAL_SIMULATOR=BJ-<issue>` (the script creates it, an iPhone 17 Pro on the newest iOS, if it is missing) or `BIRDJOURNAL_DESTINATION='platform=iOS Simulator,id=<udid>'`. Never use another agent's simulator, never shut down or erase one that isn't yours, and delete throwaway ones (`xcrun simctl delete`) when done. Without either variable the script uses "iPhone 17", which is the maintainer's.
- **Timeouts.** Nothing stalls: the Mock Device Kit suites have a 2-minute Swift Testing time limit per test, xcodebuild gets per-test allowances (`BIRDJOURNAL_TEST_ALLOWANCE`, default 180 s; `BIRDJOURNAL_TEST_MAX_ALLOWANCE`, 300 s), and a watchdog kills any run whose log is quiet for `BIRDJOURNAL_QUIET_MINUTES` (default 6). The watchdog samples the test host into the logs, shuts the run's simulator down and fails the run. `--hang-probe await|spin|silent` checks the timeouts with deliberately hung tests. macOS has no `timeout` command; never pipe xcodebuild into `head`.
- **Mock Device Kit** (DAT-SETUP-CHECKLIST.md, "Mock Device Kit fallback"): pair through `MockDeviceKitTests.withMockDisplay`, which waits for its own device and tears down in the order that keeps the toolkit's mock link alive (#82). A wedged link shows as "No connected display glasses." in every following test; it lasts until a fresh test host starts.
- **The lens in Chrome**: `BIRDJOURNAL_SIMULATOR=BJ-<n> scripts/mock-lens-in-chrome.sh ["navLeft select"]` builds, installs and launches the app in mock-lens mode and waits until the preview server answers on `127.0.0.1:9000`, so the maintainer's Chrome tab with the Meta Ray-Ban Display Simulator extension shows the lens. One simulator at a time, because the port is the Mac's: the script refuses if another process holds it. `--stop` quits the app and frees the port; `--port` picks another one. Test runs start the server only when asked (`TEST_RUNNER_BIRDJOURNAL_MOCK_PREVIEW_PORT=9000`).

Models: `scripts/download-models.sh` fetches the files in `models/manifest.json` and verifies SHA-256. Packs: `scripts/download-pack.sh` fetches the bundled pack's zip from `packs/manifest.json` (public GitHub Releases, no credentials; the `PackTests` bundle reads the bundled pack). Test clips: `scripts/download-clips.sh` fetches the entries in `fixtures/clips.json`; the engine tests skip clips that are absent. Pack builder tests: `cd packbuilder && uv run pytest`. A pack build's sounds step needs ffmpeg and a xeno-canto key in `XENO_CANTO_API_KEY` (shell profile, never the repo); it paces every xeno-canto request (see `packbuilder/README.md`), so never parallelize it or lower `--xc-interval` below its default without a reason. Its pack-art step paints on comfybox over the tailnet whatever `packbuilder/packs/<id>/art.lock.json` lacks, and only paintings the maintainer approved on the contact sheets in `build/pack-art/<id>/` (`packbuilder art-review`) go into the pack; `--no-art` skips it (`packbuilder/README.md`, "Pack art"). Backend tests: `cd backend && uv run pytest` (Docker running, for DynamoDB Local). Stack tests: `cd infra && uv run pytest` (no AWS calls). Never `cdk deploy` or `cdk bootstrap` without the maintainer's go-ahead: it creates billed resources in the shared account. Its lore step writes what `packbuilder/packs/<id>/lore.lock.json` lacks through the Anthropic API with the key in `BIRDJOURNAL_ANTHROPIC_API_KEY` (shell profile, never the repo; not `ANTHROPIC_API_KEY`), and only approved lore ships (`packbuilder lore-review`); `--no-lore` skips it (`packbuilder/README.md`, "Fact sheet and lore").

Branches: `dev` is the default branch. Feature branches open their PRs against `dev`, and a PR's `Closes #N` closes the issue when it merges there. `main` takes a merge from `dev` only to strike a release on the public beta channel, so never open a feature PR against `main`.
